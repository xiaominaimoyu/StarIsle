# Caddy 长流、取消与运行日志验证

更新：2026-11-01。范围为 S2-02 的本机容器长流验证，使用受控慢速 chat 上游；不接真实模型、生产账号或真实私有数据。公开 Pages 没有重新部署。本轮用户指令为“继续下一步开发”，沿用 [PRD](../PRD.md) 中的隔离边界。

## 已观察到的结果

初轮独立项目 `starislesse7ecc436904` 的 HTTP 与真实 Chromium 链路通过，包含 7 种上游场景：

| 场景 | 实际观察 |
| --- | --- |
| 正常慢速完成 | 保持应用原 10 秒心跳；首条 data 175.35ms，心跳在 10248.75ms / 20248.17ms 到达，正常 done 后只保存一条 assistant |
| HTTP 在 token 后关闭 | 上游 interrupted=1、active=0；检查发现已关闭用时 503.33ms；只保留 user 消息 |
| 首个 token 前关闭 | 等待到实际 heartbeat 后关闭；上游 interrupted=1、active=0，观察用时 498.32ms；无 assistant |
| 浏览器点击取消 | 原生 fetch、实际取消按钮，上游关闭，观察用时 471.88ms；前端显示已取消，数据库无 assistant |
| 浏览器离开页面 | 实际导航离开知识库，上游关闭，观察用时 490.53ms；数据库无 assistant |
| 上游 partial 后缺少 DONE | 收到 partial token 后返回 CHAT_STREAM_INCOMPLETE，没有 done，也没有保存 assistant |
| 取消后的正常请求 | 可重新完成正常请求，所有上游 active 归零 |

关闭用时包含 `docker compose exec` 查询状态的开销，是本机一次观察值；脚本要求在 5 秒检查窗口内观察到关闭，不代表生产性能承诺。浏览器为 Chromium 1440×900、reduced-motion，未替换 fetch 或拦截 RAG 响应，pageerror 为 0。无压缩 SSE 与用户/assistant 消息数量通过实际 API/SQLite 读回核对。

## 已复现的问题与修改

初轮功能虽通过，检查运行日志发现 4 条 Caddy `aborting with incomplete response` 告警。告警的 request.headers 中带有本轮测试 CSRF 值；仅不配置访问日志不能消除该问题。所有值均来自本轮随机隔离会话，测试结束后已退出并删除临时数据，本文不复制值。

新增的 `assert_safe_runtime_logs` 对实际日志做 JSON 检查。在改动 Caddyfile 之前运行，明确失败于 `Caddy runtime log contains request headers`，失败证据保存为 `logs/caddy-sse-privacy-red.log`。

在默认运行 logger 中增加 `format filter`，删除整个 `request>headers` 对象；保留告警级别、消息与其他诊断字段，不通过抑制告警来获得通过。没有修改 API/worker、数据库 schema、chat 解析或心跳周期，没有添加正式模型服务或新依赖。

该配置按 [Caddy 全局日志选项](https://caddyserver.com/docs/caddyfile/options#log) 和 [filter/delete 编码器](https://caddyserver.com/docs/caddyfile/directives/log#filter) 编写。既有 event-stream 转发仍使用默认行为，未设置负值 flush_interval；相关默认行为见 [Caddy 流式转发文档](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#streaming)。

## 隔离方式与复现

新入口 [caddy_sse_e2e.py](../scripts/caddy_sse_e2e.py) 复用既有 Compose base/local 和 Caddyfile，临时覆盖层内加入 [慢速上游 fixture](../scripts/fixtures/caddy_slow_chat.py)。仅 Caddy 映射 loopback，fixture/API/worker 均无宿主端口；fixture 只保存有限场景计数，不保存提示词或凭据。API 密码与签名值随机生成，只写本轮临时 env 文件；展开后的 Compose 配置只在内存核对，不写日志。

前端以启用本地认证的正常模式构建到系统临时目录，公开 Pages dist 保持独立。每次运行使用随机项目名与新的 `logs/starislesse*` 证据目录；正常及失败退出均执行本轮 Compose down，核对本轮容器/卷/网络，删除本轮镜像标签，临时目录由既有安全 helper 管理。不停止其他项目或清理共享缓存。

前提：本机 Linux Docker 引擎可用，项目既有 pnpm/API 虚拟环境及 Playwright Chromium 已安装。在仓库根目录执行：

```powershell
$env:PYTHONIOENCODING = 'utf-8'
.\apps\api\.venv\Scripts\python.exe -B scripts/caddy_sse_e2e.py
```

其他已配置 Linux context 可通过 `--context` 明确指定。脚本输出本轮证据路径，内含 result.json、源文件 SHA-256、构建/启动/服务日志/清理结果。证据在既有 logs 忽略范围，测试配置、数据、原始输出均不提交。
