# 邮件与相册失败恢复

更新：2026-11-04。用户继续完善项目，从已推送的 main@4c1efb5 干净工作区开工。范围沿用“公开站上线＋私有功能本地可用”；本批只完善本地私有界面，不重新发布公开站，不处理宿主 Docker。

## 已完成行为

邮件详情在手机上加载中或失败时，列表已隐藏而返回按钮仅存在于正文成功分支，用户无法换一封邮件。列表轮询/刷新/分页也会用骨架或错误卡替换已有行，失败不能明确重试原分页游标。现在邮件加载、失败均可返回列表，焦点回原邮件行；迟到详情不再渲染或继续发起已读写入。刷新和分页保留已有行、分别提示错误，失败分页重试原游标；防止重复分页和并发首屏刷新改写失败游标。

正文 GET 完成即可阅读，不等待独立的已读 POST；写入失败单独提示并允许重试。切换邮件后，上一封迟到的已读失败不会覆盖当前邮件的重试提示；各邮件行仍独立回滚未读状态。已开始的请求没有被描述为自动取消。

相册上传或删除成功原先会重载第一页，先隐藏旧照片，再丢掉已有尾页；失败时也无法继续浏览旧图。现在刷新合并最新第一页与已浏览内容，保留照片和操作入口、按 ID 去重，过滤已删除项；失败可重试，过期响应不能清除新请求状态。

照片按拍摄日期排序，新上传的旧照片可能位于尾部或已浏览区间中间。因此上传后的下一次成功刷新采用新首屏游标，允许重新读取重叠页并去重，避免新图不可达；刷新失败时保留重扫标记直到重试成功。删除等普通刷新保留已推进的非空边界；服务端确认存在后续页时允许已耗尽游标重新开启。此前“所有刷新永久保护旧游标”的建议已由真实回归证明不完整，没有保留这条错误规则。

产品修改限定 MailInbox.tsx 和 PhotoTimeline.tsx；新增两份真实 DOM 回归，扩展现有浏览器验收入口。API/契约、schema、依赖、Cookie/CSRF、远程图片默认阻止、视觉和上传并发规则保留。
