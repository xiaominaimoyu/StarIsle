- 密码显示/隐藏按钮实际切换 input.type，并保留输入值和键盘焦点；补充 aria-pressed/aria-controls。按钮宽 44px，覆盖整个输入框高度，桌面及窄屏可用。

- SessionGate 收到明确 CSRF_REQUIRED 后清除失效令牌，保留页面，由用户点击重试重新握手；不自动重放 refresh 或写请求。页面卸载后不继续进入下一段鉴权请求。
- 无权访问卡片增加“重新登录”，保留原路径与查询参数；确认失效的会话仍走原登录跳转，临时服务错误仍留在原页允许重试。

## 真实后端与受控故障的区别

正常恢复场景未替换鉴权响应：在本轮独立浏览器上下文删除测试 access Cookie，真实 auth/me 返回 401，原 SessionGate 发起 refresh 200。检查新的 access Cookie 为 HttpOnly，refresh Cookie 值已轮换，随后真实 auth/me 200；没有读取或解析 JWT。该场景模拟 access Cookie 缺失，不声称测量了真实 JWT 的到期时钟。

故障场景只替换第一次 CSRF 握手的响应值，后续放行。真实 API 拒绝该测试令牌并返回 refresh 403；页面显示可重试错误、没有自动重放。点击重试后取得真实新 CSRF，真实 refresh 200，再次 auth/me 200。另一场景临时返回 auth/me FORBIDDEN，用于验证新增按钮；撤销替身后真实登录并回到 /console/files?view=recent。替身均在 finally 撤销，不把注入的状态当作真实账号权限变化。

本批后端验证经 Astro 开发代理；没有重跑 Caddy 容器的 refresh 场景。11-01 的 Caddy 基础登录/退出、长流及日志过滤证据保持其原范围，不能据此合并声称完整生产认证验收。

## 失败与资源清理

第一次完整浏览器扩展已经走通真实 refresh 和 CSRF 重试，但把 FileTable 中设计为 hidden 的原生文件 input 当作可见控件等待，导致该轮失败。检查 DropZone 实现后，改为核对授权分支可见及文件 input 已挂载；真实文件上传检查保留在后续原流程。最终完整回归通过，首轮日志保留。

第一次单独视觉检查中 UI/构建均通过，进程树停止也成功，但即时端口检查仍能建立连接，因此整轮记录为 failed；随后独立查询已无监听。验收脚本改为最多 5 秒等待端口释放，仍保留必须释放的断言；最终观察约 2.14 秒后端口释放。没有为此修改项目进程管理 helper，也没有按端口终止其他进程。

本轮自有 API/worker/Web、浏览器、临时构建目录均已退出清理。原已发布 dist 的 55 文件逐项 SHA-256 保持不变，原完整门禁仍通过，聚合 fingerprint 为 9e29df03aa211bae144ec555f854c3cf5de75db4ee518fd2f0286727b83f85b0。这是旧发布制品未被覆盖的证据，不是新构建候选已通过完整 Pages 发布门禁或已上线的证明。
