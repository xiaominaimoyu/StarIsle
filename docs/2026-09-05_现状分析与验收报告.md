## 1. 结论摘要

StarIsle 已不是早期计划文档所描述的空仓库，而是一个结构完整、可在本机重复构建和隔离测试的全栈候选：Astro 5 + React 19 Islands 构成静态公开站与私有 Console，FastAPI 提供同源 `/api/v1`，SQLite schema v5 保存私有数据，Cloudflare Email Worker 参考实现负责邮件入口，durable worker 负责知识库任务与维护任务，Caddy/Compose 文件描述部署拓扑。

本轮完成了当前工作区内能够安全、明确闭环的高置信缺口，包括：`/enter` 首阶段叙事入口、真实 session 状态校验、WebP 魔数修正、请求体门禁聚合、作业列表/取消/存储统计、JWT `kid` 轮换、邮件 HMAC `kid` 轮换、四个列表的稳定复合游标、知识文档前端分页，以及照片时间严格规范化、标准 Exif 子 IFD 读取、Orientation 校正、语义排序、同日分组和迟到响应保护；浏览器夹具数据库也增加父进程自有临时栈能力校验。后续叙事增量已形成 Phase 4 的共享登录嵌入候选、Phase 6 的 projected deterministic geometry/Mask，以及只在 Console 认证成功分支动态加载的 Phase 7 pointer `TearPortalLink` 候选。相应单元测试、静态检查、生产构建和隔离 Chromium 认证/交互/降级反例均已补齐；当前可运行的非发布本地门禁通过。

项目仍不能标记为 M1、M2 或 M3 完成。原因不是还有一个可由源码伪造的“最后按钮”，而是验收基线明确要求真实域名、经授权个人内容与媒体、移动端 Lighthouse、Docker/Caddy/TLS/CDN/Cloudflare 运行证据、生产恢复、真实 GGUF、至少 20 篇授权文档、30 题评测及指定硬件性能记录。这些输入或环境当前不存在。`pnpm build:release` 也按设计以 `CONFIG_INVALID_URL` 拒绝发布。

因此，当前准确状态是：**本地工程候选通过；发布候选未形成；生产验收未通过。**

## 6. 本轮实现与缺陷修复

### 6.1 体验与发布边界

- 新增 `/enter` 首阶段，仅作为 opt-in 叙事入口，不改 `/` 的 SEO 和公共分享语义。无 JavaScript 时仍有真实 `/`、`/login` 链接，页面 `noindex`，减弱动效可直接揭示下一步。
- 发布制品门禁新增 `/enter/index.html`、noindex、无 canonical/`og:url`、静态回退链接与 sitemap 排除检查。
- `README.md` 已删除“当前文件已受版本控制”的错误表述；叙事设计文档改为“首阶段本地原型已实现，后续仍 Proposed”。

### 6.2 认证、上传与请求边界

- `/auth/me` 现在查验真实 session 是否存在、未撤销且未过期，不再只信任 JWT 声明。
- WebP 上传魔数判定已按 RIFF/WEBP 格式修正。
- 请求体门禁按规范化路由标签聚合，避免动态 ID 产生无界指标标签。
- 部署预检的环境变量 allowlist 使用 Windows 大小写不敏感语义，阻止宿主同名变量混入合成配置。

### 6.3 作业、统计与 Console

- 新增 `GET /jobs`、`POST /jobs/{job_id}/cancel`、`GET /stats/storage`，并在写锁内处理取消与 worker 竞争。
- 取消会保持文档状态与审计语义一致；Console 总览和知识库界面可恢复活动任务、显示统计、取消与重试。

### 6.4 密钥轮换

- JWT 使用 `AUTH_JWT_ACTIVE_KID` 与至多 4 把 `AUTH_JWT_PREVIOUS_KEYS_JSON`；新 token 在 header/payload 同时绑定 `kid`，验签只精确选择一把 HS256 key，未知/缺失/不一致均拒绝。
- 邮件新协议使用 `X-Mail-Key-Id` 和 `v1.{kid}.{timestamp}.{nonce}.{body_sha256}`。API 只精确选择 active/previous 中的一把 key；无 header 的 legacy 请求永远只使用当前 `MAIL_HMAC_KEY`，不会扫描旧 key。
- Worker 未配置 active kid 时保持 legacy，便于按“先 API、再 Worker、最后轮换 secret”的顺序迁移；真实 Cloudflare 轮换仍需部署所有者执行。

### 6.5 稳定分页

- `/files`、`/photos`、`/mail`、`/knowledge/documents` 从纯时间游标改为版本化 `(sort_value, id)` 降序 keyset 游标，并绑定 endpoint scope；files 的 MIME filter 与 mail 的 unread filter 也绑定游标上下文。
- 旧纯时间游标固定返回 422，避免静默漏项；游标属于短期页面状态，客户端应重新从第一页获取。
- `DocumentManager` 保存 `nextCursor`、支持“加载更多”、追加去重、错误重试，并以 revision 防止过期请求覆盖上传、删除或 job 状态；隔离浏览器夹具验证 20 + 1 条跨页结果完整无重。

### 6.6 照片时间与前端一致性

- `DateTimeOriginal` 现被明确建模为无时区的相机当地墙钟时间。API 严格接受 legacy EXIF 与 canonical 两种秒级格式，验证真实日历后统一返回 `YYYY-MM-DDTHH:MM:SS`；不读取 offset 来猜测历史 instant，非法/缺失值投影为 `null`。
- API 先读取标准 Exif 子 IFD 中的 `DateTimeOriginal`，再兼容既有非标准顶层值；上传时在原始 header 尺寸门禁后执行 `ImageOps.exif_transpose`，数据库宽高和 WebP 缩略图都按视觉方向生成，避免 Orientation=6 等手机/相机竖拍图横倒。
- SQLite 每个应用连接注册 deterministic `photo_capture_norm`。照片列表先按“有效拍摄时间”与“未知日期”分域，再分别按 canonical capture 或 `created_at` 倒序；旧数据无需迁移。照片 cursor scope 更新为 `photos.timeline-local.v2`，旧排序游标固定 422。
- `PhotoTimeline` 不再创建宿主时区 `Date`，而是直接做 Gregorian 字段校验并生成稳定 `YYYY/MM/DD` 标签；legacy/canonical 同日稳定归组，非法值进入“未知日期”。游标页按 ID 去重，request revision 保证最新请求胜出，删除会失效先前列表请求，延迟刷新在卸载时清理，加载更多失败保留既有照片和独立重试入口。
- 新增 Python 规范化单测、混合历史值/游标 HTTP 集成、标准嵌套 Exif JPEG 与 Orientation=6 上传集成、Web 日期/分组/去重单测，并在隔离浏览器临时库验证 legacy/canonical 同日只产生一个分组。

### 6.7 Harness 隔离与测试稳定性

- 浏览器照片/job fixture 只能写入父进程本轮创建的系统临时栈：数据库须精确等于临时 `DATA_ROOT/db/star-isle.db`，路径及父链不得含 symlink/reparse point，并须匹配不经 argv 传递的随机 capability marker。直接以 `--external-services --isolated-fixture-db <真实库>` 调用会在进入浏览器流程前固定拒绝，回归测试同时验证 canary 数据未改变。
- `test_popen_parse_failure_reaps_sibling_runner_without_waiting_for_default_timeout` 原用 0.1 秒覆盖 Windows gate bootstrap 与目标 Python 的两段冷启动，历史上可稳定误报 timeout。现在使用有界 5 秒预算，并以实际耗时 `<10 秒` 继续证明失败路径不会等待默认 45 秒；没有 skip 或 xfail。
- 同一用例由独立进程连续运行 5 次均通过，整份 `test_recovery_drill.py` 61/61 通过；加入照片与 harness 回归后，API 全量为 603/603 通过。

### 14.1 代码与架构结论

- Phase 6 复核修正了两个会影响真实交互的反例：弧长/sampler 现在按 `1000 × 240` 投影坐标派生，避免非等比 SVG 下的速度偏差；Mask 现在用透明底和渐进白色 stroke 揭示注入 surface，不再形成 identity mask。canonical seed 也统一为单一常量。
